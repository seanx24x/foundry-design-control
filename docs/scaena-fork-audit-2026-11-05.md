# Scaena Fork review — 5 November 2026

Reference: https://scaena.darkroom.engineering/#pad-value-drag

All 17 scenes were opened in the live browser, with the Fork variant selected where applicable. Full Pane exposes upstream and Fork together. This is a visual/interaction review, not a claim that every possible input combination or gesture in the reference was tested. Sound stayed off. Light and dark treatments were observed; most detailed scene inspection was in light. No reference code or assets were copied.

## Implemented in this slice

- Compact input runs are packed in pairs; an unpaired input fills its row, including before a full-width field.
- Every custom select inside an Inspector field anchors to that entire field; menu bounds still respect the viewport.
- Object position uses a quiet X/Y summary and a spatial editor, with nine anchors, exact per-axis entry, a direct-manipulation pad and CSS fallback.
- Narrow shell intrinsic sizing is bounded so a child cannot widen the entire Inspector beyond a 320px viewport.

## Ordered follow-up checklist

- [ ] Context help: hold-to-explain with equivalent keyboard/focus/touch entry and robust release/blur cleanup.
- [x] Long panes: current-section sticky treatment in desktop studio property rails, with no stacked-header occlusion; normal flow in compact stacked panes.
- [x] Motion Studio: coordinated curve/coordinate/preset composition, based on actual authored tracks; local easing draft with explicit Use/Cancel and retained captured source.
- [ ] Background editor: more compact stop rows and capability-gated reorder/gradient types.
- [ ] Color: capability-safe wide-gamut channels and eyedropper, preserving original syntax until edited.
- [ ] Direction/variant menus: compact actions only where the underlying data model genuinely supports them.

These are not marked shipped merely because the reference was reviewed. No application source Apply, npm publication or production deployment is part of this UI refinement pass.
