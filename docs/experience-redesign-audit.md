# Foundry experience redesign: capability and state baseline

Date: 16 September 2026. Baseline: the local `0.2.0-beta.22` development checkout, including existing uncommitted work. This is an evidence inventory, not release certification.

## Audit boundaries and evidence labels

This pass inspected current inspector source, tests, existing reports, and the earlier recording-flow audit and fixes. It did **not** start or stop a session, change a recording, run fresh tests, or visually inspect a new browser session. Existing recording projects and source changes must remain untouched.

- **S — Source-inspected:** the capability or state has a current implementation. This does not prove correct runtime behavior.
- **C — Contract-test coverage:** test source contains assertions. Most inspector smoke tests inspect source strings, not a rendered browser; do not describe them as UX verification.
- **B — Browser-test coverage:** an executable browser scenario exists. Existing reports, where listed, are historical results rather than a run from this audit.
- **V-historical — Previously visually observed:** recorded in the earlier human-paced recording-flow audit or fixes. It does not certify the redesigned build.
- **N — Not yet audited:** needs a fresh, deliberate interaction and visual pass, including failure/recovery. Every redesigned destination starts at N for visual acceptance.

Evidence inspected:

1. `apps/inspector/public/index.html`, `app.js`, `styles.css`, `workflow.js`, and inspector tests.
2. `scripts/test-showcase.mjs`: 29 historical checks at 1920×1080 and 1280×1080; report files under `artifacts/showcase-1920` and `artifacts/showcase-1280` report passed. Some checks only visit and capture a destination. They are not complete functional coverage of that destination.
3. `artifacts/heading-rehearsal/report.json`: historical real reviewed 76px → 54px heading Apply, source diff, rebuild, measured verification, Delivery and History; light/dark measurements and queued-session recovery recorded.
4. `artifacts/recording-rehearsal/report.json`: historical real reviewed button width/max-width Apply, source diff, rebuild, measured verification, Delivery and History; six viewport/theme measurements recorded.
5. `FOUNDRY_FLOW_AUDIT_2026-09-16.md` and `FOUNDRY_FLOW_FIXES_2026-09-16.md` in the project workspace: human-paced 1367×898 observations and subsequently recorded fixes. Historical issue line numbers can have moved.
6. `examples/compatibility/README.md` documents earlier React/Vite, Next and Storybook/CVA results. Its referenced `artifacts/compatibility` directory is absent in this checkout at audit time, so this pass does not independently corroborate those reports.

## Concrete current shell and Review issues

Line references were captured before redesign edits; the symbols remain the stable lookup keys.

1. **P1: Review conflates exclusion with unresolved mapping.** In `app.js:2218`, `unresolvedCount` is `changes.filter((change) => !validChange(change)).length`, while `validChange` at `:2154` requires approval as well as valid mapping. A perfectly mapped draft/rejected/applied row can therefore cause “Source mapping: Review.” Count mapping problems independently and scope batch metrics to included changes; test mixed-status groups.
2. **P1: Review understates impact and invents certainty.** The summary at `app.js:2269` uses “Local styles” whenever the above count is zero and falls back to one affected file when no source file is known. Component variants, token promotion and font source plans are not all local style edits. Derive impact from reviewed operation semantics and exact selected mapping; unknown stays unknown.
3. **P2: Row-level comparison is not visible or row-specific.** `app.js:2302` binds every “Preview before” button to global `toggleComparison('before')`; `:7482` sends only `{mode}`. Review remains active and Canvas is hidden. Replace this with an explicitly global visible comparison, or show the selected target with accurately scoped before/after evidence. Do not imply per-row comparison when the operation is global.
4. **P2: Navigation does not expose the studio model or Review consistently.** `index.html:97–154` contains thirteen icon-only destinations with no visible labels/groups or Review entry. `renderChangeSummary` at `app.js:2471` hides the Review/count surface outside Canvas. Introduce labeled Design/Test/Collaborate groups and persistently accessible Review/count without relying on the menu, tooltip or prior knowledge.
5. **P2: Connection/error feedback requires inference.** `renderConnectionStatus` at `app.js:445` visibly says “Live” whenever the preview is connected, while listener availability is only in the title/readiness detail. `toast` at `:438` dismisses durable-action errors after 1.8 seconds. Surface separate preview/agent states and persistent, local recovery for consequential failures. A correct underlying error is not sufficient if the user cannot retain or act on it.

Also check the center region's fixed accessible name “Foundry canvas” (`index.html:183`) across non-Canvas modes. The new navigation should update semantic context as well as visual highlighting.

## First vertical slice: prioritized acceptance gate

1. **Unify the shell without losing context.** Labeled collapsible navigation, compact shared header, separate preview/agent status, permanent Review count, stable focus and coherent panel boundaries. Selection, branch, viewport/theme/state and staged edits survive every transition.
2. **Make one precise edit explain itself.** Source-mapped selection → measured control → temporary preview → included Review. Resolve exact destination and impact before approval. Include no-selection, unmapped, excluded and stale-source cases, not only the happy path.
3. **Make comparison and execution observable.** The user can actually see baseline and candidate in matched context. Queue truthfully while listener is offline; claimed source work and rebuilt verification remain separate. Preserve input on error and require explicit retry.
4. **Close with evidence, not celebration alone.** Verify a real source delta and rendered value, then expose the matching Delivery contract, evidence and History. Repeat in Morrow and React/Vite; never mutate a recording take for acceptance testing.
5. **Obtain approval before expanding.** Present the working slice plus editable light/dark Figma components. The approved plan makes this the design gate before rolling the visual system across all studios and the website. No publication is part of this audit.

Fresh slice validation must cover 1280×800, 1440×900 and 1920×1080; light/dark; 200% text scaling; keyboard/focus; reduced motion; long labels; deliberate pauses; preview/listener disconnects; one verification mismatch; and navigation mid-operation. Record environment and source revision with each new result. Only upgrade an N state to visually verified after that state was actually exercised and inspected.

## Branch acknowledgement regression prevented during this slice

**S/C — Source-inspected and covered by focused behavior tests:** when a runtime design branch is active, `SessionStore.addOperationWithChange` stores its correction in `designBranches[].changes`. The new strict acknowledgement initially read only the main ledger. Before acceptance, `record()` was corrected to inspect the authoritative active branch ledger and reject a missing or unrelated branch instead of claiming main-Review success. This is distinct from the corrected main-direction 40px → 40px transitional-read defect.

Branch corrections now keep their acknowledged preview and say “Saved to direction”; promotion remains necessary before main Review. Focused tests cover active-branch success, missing-branch rejection and rollback. Full branch interaction remains a separate browser acceptance item: do not infer it passes from the main-direction golden path. No source application occurs merely because a correction was recorded.
